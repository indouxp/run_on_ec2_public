# run_on_ec2 見送り事項一覧

## 概要

本文書は、run_on_ec2 プロジェクトにおいて、今回のリリースでは対応せず、次期以降に見送る事項を一覧化したものです。

## 見送り事項

| No. | 事項 | 詳細 |
|-----|------|------|
| 1 | ECS への移行 | 現行の EC2 上での実行を、ECS (Elastic Container Service) によるコンテナベース実行に切り替えます。 |
| 2 | GUI 画面でのオペレーション | ファイル入力から結果取得までの一連の操作を、GUI 画面上で完結できるようにします。対象 OS は Ubuntu、ZorinOS、Windows です。 |
| 3 | EC2 インスタンス削除処理の簡素化 | **現状**: EC2 のシャットダウンを EventBridge が検知し、Lambda 関数 `ts-010-lmd-020` が当該インスタンスを削除する 3 段構成となっています。<br>**改善案**: Lambda を介さず、EC2 起動時（または Launch Template）で `InstanceInitiatedShutdownBehavior`（インスタンスによるシャットダウン時の動作）を `terminate`（削除）に設定し、インスタンス自身のシャットダウン動作で削除されるように変更します。 |
| 4 | パッケージインストールの事前化 | **現状**: UserData 内で `ffmpeg` や `pigz` を毎回インストールしているため、起動のたびに時間を要しています。<br>**改善案**: 必要なツールをインストール済みの **AMI（ゴールデンイメージ）** を事前に作成し、それを用いて EC2 を起動します。 |
| 5 | 同時実行数の制御 | **現状**: ファイルが同時に 100 個アップロードされると Lambda が 100 回起動し、EC2 も 100 台起動しようとします。これは AWS アカウントの vCPU 制限（サービスクォータ）に抵触し、エラーとなる可能性が高い状態です。<br>**改善案**: S3 イベントの後段に **SQS（キュー）** を挟み、Lambda または EC2 がキューからメッセージを取り出して処理する Producer-Consumer 構成とし、同時実行数を制御します。代替案として **AWS Batch** の採用も検討候補となります。 |
| 6 | ffmpeg 異常終了時のログ消失対策 | **現状**: 変換処理中に `ffmpeg` がメモリ不足等で異常終了した場合の考慮が不足しています。エラー時にそのままシャットダウンされると、S3 へのアクティビティログアップロード前に EC2 が消失するため、原因追跡が困難となります。<br>**改善案**: エラー時はシャットダウンせず「停止」状態に留めて調査可能とする、または CloudWatch Logs へリアルタイムにログを転送する設定を導入します。 |
| 7 | S3 ファイル削除の自動化 | **現状**: オペレーターが手作業で S3 からファイルを削除しています。人手を介する運用はオペレーションミスの温床となります。<br>**改善案**: S3 の **ライフサイクルポリシー** を設定し、「作成から X 日後に自動削除」または「変換完了タグが付与されたら削除」とする運用に変更します。 |
