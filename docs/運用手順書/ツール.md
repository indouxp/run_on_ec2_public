## 2. 運用ツール一覧

ツールは `work/` ディレクトリに格納されています。

### 2.1 mk-run.conf.sh — 定義ファイルの対話的作成

`work/run.conf.skl` をデフォルト値として読み込み、対話的に `run.conf` を作成します。

```bash
cd work/
./mk-run.conf.sh
```

- 各項目のプロンプトが表示されます。デフォルト値のままでよい場合は Enter を押してください
- 生成された `run.conf` は JSON 形式で `work/run.conf` に保存されます
- デフォルト値のひな形は `work/run.conf.skl` を編集して変更できます

---

### 2.2 upl-run.sh — S3 へのアップロード（システム起動）

`ts-010-role-exec` ロールを Assume し、入力ファイル・`run.sh`・`run.conf` を S3 に順次アップロードします。`run.conf` のアップロードが Lambda のトリガーとなり、処理が自動起動します。

```bash
cd work/
./upl-run.sh
```

- 実行ログは `work/upl-run.sh.log` に記録されます
- アップロード先: `s3://${BKT_IN}/`

---

### 2.3 aws-pop-bktobj.sh — 結果ファイルのダウンロードと削除

`${BKT_OUT}` 内の全オブジェクトをダウンロードし、サイズ確認後に S3 から削除します。

```bash
source work/.env   # 未実施の場合のみ（AWS_ACCOUNT_ID が必要）
cd work/
./aws-pop-bktobj.sh [バケット名]
```

- バケット名省略時は `${BKT_OUT}` を対象とします
- ダウンロード先: `work/downloaded_files/`（自動作成）
- ローカルファイルサイズと S3 サイズが一致した場合のみ S3 から削除します

> **注意**: EC2 が完全に停止・削除されてからダウンロードしてください。

---

### 2.4 aws-del-bktobj.sh — 入力バケットの全削除

`${BKT_IN}` 内の全オブジェクトを削除します。

```bash
source work/.env   # 未実施の場合のみ（AWS_ACCOUNT_ID が必要）
cd work/
./aws-del-bktobj.sh [バケット名]
```

- バケット名省略時は `${BKT_IN}` を対象とします

---

### 2.5 reissue-accesskey.sh — ts-010-user アクセスキーの再発行

`ts-010-user` のアクセスキーを新規発行し、`~/.aws/credentials` の `[default]` プロファイルを更新します。`mk-iam-user.sh` 再実行後や認証情報が無効になった場合に使用します。

```bash
cd infra/
./reissue-accesskey.sh
```

- `ts-usr-admin` プロファイルで `create-access-key` を実行します（`AWS_PROFILE` のセットは不要）
- 実行後に `aws sts get-caller-identity` で `ts-010-user` の ARN が返れば更新成功です
- キーが上限（2個）の場合は事前に1個削除してください

```bash
# キー上限の場合：古いキーを削除してから実行
AWS_PROFILE=ts-usr-admin aws iam list-access-keys --user-name ts-010-user --output text
AWS_PROFILE=ts-usr-admin aws iam delete-access-key --user-name ts-010-user --access-key-id <古いKeyId>
./reissue-accesskey.sh
```

### 2.6 aws-get-lambda-functions.sh — Lambda 関数一覧の確認

アカウント内の Lambda 関数を一覧表示します。

```bash
cd work/
./aws-get-lambda-functions.sh [-p プロファイル] [-r リージョン] [-o 出力ファイル]
```

| オプション | 説明 |
|-----------|------|
| `-p` | AWS プロファイル名（省略時は CLI 設定に従う） |
| `-r` | リージョン（省略時は CLI 設定に従う） |
| `-o` | 結果を保存するファイルパス（省略時は標準出力） |

---

### 2.7 aws_get_log_groups.sh — CloudWatch ロググループ一覧の確認

CloudWatch Logs のロググループ一覧（名称・保持期間・サイズ・作成日時）を表示します。

```bash
cd work/
./aws_get_log_groups.sh [-p プロファイル] [-r リージョン] [-o 出力ファイル]
```

| オプション | 説明 |
|-----------|------|
| `-p` | AWS プロファイル名（省略時は CLI 設定に従う） |
| `-r` | リージョン（省略時は CLI 設定に従う） |
| `-o` | 結果を保存するファイルパス（省略時は標準出力） |

特定のロググループのログをリアルタイム監視する場合は AWS CLI を直接使用します:

```bash
# Lambda 起動関数のログ監視
aws logs tail /aws/lambda/ts-010-lmd-010 --follow

# EC2 処理ログの監視
aws logs tail ts-010-log-ec2-010 --follow
```

---

### 2.8 aws-get-lastlog.sh — CloudWatch 最新ログの取得（システムユーティリティ）

指定したロググループの最新ログストリームを取得し、全イベントを出力します。
Lambda や EC2 のエラー調査に使用します。

> このスクリプトはプロジェクト外のシステムユーティリティ（`~/bin/aws-get-lastlog.sh`）です。`work/` には含まれません。

```bash
aws-get-lastlog.sh <ロググループ名>
```

**使用例:**

```bash
# Lambda 起動関数の最新ログを取得
aws-get-lastlog.sh /aws/lambda/ts-010-lmd-010

# EC2 処理ログの最新ログを取得
aws-get-lastlog.sh ts-010-log-ec2-010
```

### 3.1 aws-cat-user_data_template.sh — デプロイ済み UserData の確認

Lambda にデプロイされている `user_data_template.sh` の内容を表示します。デプロイ内容の確認に使用します。

```bash
cd src/shell/
bash aws-cat-user_data_template.sh
```

- `config.sh` の `LAMBDA_FUNC_NAME` で指定された Lambda 関数のコードをダウンロードして展開します
- 実行結果は `src/shell/aws-cat-user_data_template.sh.log` にも記録されます
- 依存コマンド: `aws`, `curl`, `unzip`
