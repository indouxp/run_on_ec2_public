# mk-route-table.sh 詳細設計書

## 1. 概要

### 1.1 目的

本スクリプトは、VPC のメインルートテーブルにインターネットゲートウェイ（IGW）へのデフォルトルート（`0.0.0.0/0`）を追加します。既存の同ルートが存在する場合は削除してから再作成します。また、ルートテーブルに Name タグとプロジェクトタグを付与します。

設定するリソース:
- VPC メインルートテーブルへのルート追加
  - 宛先: `0.0.0.0/0`
  - ゲートウェイ: `ts-010-igw-010`（インターネットゲートウェイ）
- ルートテーブルへのタグ付与（Name: `ts-010-rtb-010`）

## 2. 実行環境

- 実行場所: `infra/` ディレクトリ
- 必要コマンド: aws cli
- AWS 認証: `source assume-role.sh`（`ts-010-role-build` を AssumeRole）

---

## 3. 前提条件

- VPC（`ts-010-vpc-010`）が作成済みであること
- インターネットゲートウェイ（`ts-010-igw-010`）が作成済みかつ VPC にアタッチ済みであること

---

## 4. 入力

### 4.1 設定ファイル（config.sh）

| 変数名 | 説明 | 例 |
|:---|:---|:---|
| `VPC_NAME` | ルートテーブルが属する VPC の名前タグ | `ts-010-vpc-010` |
| `IGW_NAME` | デフォルトルートの向き先となる IGW の名前タグ | `ts-010-igw-010` |
| `ROUTE_TABLE_NAME` | ルートテーブルに付与する Name タグ値 | `ts-010-rtb-010` |
| `PRJ_TAG_KEY` | プロジェクト識別用タグキー | `PRJ_NAME` |
| `PRJ_TAG_VALUE` | プロジェクト識別用タグ値 | `ts-010` |

### 4.2 引数

コマンドライン引数はありません。

## 5. 処理フロー

### 初期化

1. `config.sh` を読み込み、環境変数を設定する。
2. 作業用一時ディレクトリ（`mk-route-table.sh.src`）を作成する。
3. `trap` を設定し、ERR / INT / TERM シグナル発生時に `term()` を呼び出して一時ディレクトリを削除し、`exit 1` で終了する。EXIT シグナルでも `term()` を呼び出す。
4. ログファイル（`mk-route-table.sh.log`）へのリダイレクトを設定する（`exec >> LOG_PATH 2>&1`）。

### `confirm_route_table()` — 実行前後の確認

5. `aws ec2 describe-vpcs` で `VPC_NAME` タグに一致する VPC の ID を取得する。
6. `aws ec2 describe-route-tables` で VPC に属するルートテーブルの ID を取得する。
7. VPC 名・ルートテーブル ID・現在のルート一覧を表示する。

### `add_igw_route()` — ルート追加処理

8. `aws ec2 describe-vpcs` で VPC ID を取得する。
9. `aws ec2 describe-route-tables` でルートテーブル ID を取得する。
10. `aws ec2 describe-internet-gateways` で IGW ID を取得する。IGW が存在しない場合はエラー終了する。
11. 現在のルートテーブルに `0.0.0.0/0` ルートが存在するか確認する。
    - 存在する場合: `aws ec2 delete-route` で既存ルートを削除する。
    - 存在しない場合: 新規追加として続行する。
12. `aws ec2 create-route` で `0.0.0.0/0 → IGW_ID` のルートを追加する。
13. `aws ec2 create-tags` でルートテーブルに Name タグ（値: `ROUTE_TABLE_NAME`）とプロジェクトタグを付与する。

### メイン処理の流れ

14. 実行前に `confirm_route_table()` を呼び出してリソース状態を記録する。
15. `add_igw_route()` を呼び出してルートを追加する。
16. 実行後に `confirm_route_table()` を再度呼び出して結果を確認する。

## 6. 作成・更新リソース

| リソース種別 | リソース名 | 操作内容 |
|:---|:---|:---|
| ルートテーブルのルート | `0.0.0.0/0 → ts-010-igw-010` | 既存削除→新規追加 |
| ルートテーブルのタグ | `ts-010-rtb-010` | Name タグ・プロジェクトタグの付与 |

---

## 7. エラーハンドリング

- スクリプト先頭に `set -euo pipefail` を設定し、コマンド失敗・未定義変数参照・パイプエラーで即時終了する。
- `trap 'term; exit 1' ERR INT TERM` により、異常終了時は作業用一時ディレクトリを自動削除する。
- `trap 'term' EXIT` により、正常終了時も一時ディレクトリを削除する。
- IGW が見つからない場合は `exit 1` でスクリプトを終了する。
- すべての処理ログは `mk-route-table.sh.log` に記録される。
