# info-all.sh 詳細設計書

## 1. 概要

### 1.1 目的

本スクリプトは、プロジェクト（`ts-010`）が作成した全 AWS リソースの情報を出力します。インフラの同一性証明・削除前バックアップ・構築確認チェックリストの補助として使用します。`--save` オプション指定時はタイムスタンプ付きログファイルにも保存します。

出力する情報:
- IAM: ロール（信頼ポリシー・管理ポリシー・インラインポリシー）、インスタンスプロファイル、ユーザー
- ネットワーク: VPC（DNS 設定含む）、IGW、サブネット、ルートテーブル、セキュリティグループ
- S3: バケット一覧、バケットポリシー、ライフサイクル、バージョニング、暗号化
- CloudWatch: ロググループ（保持期間・メトリックフィルター）
- SNS: トピック、サブスクリプション
- Lambda: 関数設定（コードハッシュ・環境変数・ロール）
- EventBridge: ルール、ターゲット
- EC2 キーペア
- CloudTrail: 証跡、イベントセレクター

## 2. 実行環境

- 実行場所: `infra/` ディレクトリ（または `src/shell/` から直接実行）
- 必要コマンド: aws cli、python3
- AWS 認証: `AWS_PROFILE=ts-usr-admin`（`ts-usr-admin` プロファイルを使用）

> **注意**: `assume-role.sh` で設定した一時認証情報（`AWS_ACCESS_KEY_ID` 等の環境変数）が残っている場合はプロファイルより優先されます。実行前に `unset AWS_ACCESS_KEY_ID AWS_SECRET_ACCESS_KEY AWS_SESSION_TOKEN` を実行してください（`work/alias.txt` の `unset-aws` エイリアス使用可）。

## 4. 入力

### 4.1 設定ファイル（config.sh）

| 変数名 | 説明 | 例 |
|:---|:---|:---|
| `PRJ_PREFIX` | プロジェクトプレフィックス（リソース検索に使用） | `ts-010` |
| `IAM_ROLE_BUILD_NAME` | 構築用ロール名 | `ts-010-role-build` |
| `IAM_ROLE_EXEC_NAME` | 実行用ロール名 | `ts-010-role-exec` |
| `IAM_ROLE_LAMBDA_NAME` | Lambda 実行ロール名 | `ts-010-role-lambda-010` |
| `IAM_ROLE_EC2_NAME` | EC2 実行ロール名 | `ts-010-role-ec2-010` |
| `IAM_USER_NAME` | IAM ユーザー名 | `ts-010-user` |
| `VPC_NAME` | VPC 名タグ | `ts-010-vpc-010` |
| その他各リソース名変数 | — | — |

### 4.2 引数

| 引数 | 説明 |
|:---|:---|
| `--save` | 出力をタイムスタンプ付きログファイル（`info-all.sh.YYYYMMDD_HHMMSS.log`）にも保存する |

## 5. 処理フロー

### 初期化

1. `config.sh` を読み込み、環境変数を設定する。
2. 第 1 引数（`$1`）を `SAVE_FLAG` として取得する（省略時は空文字）。
3. `--save` が指定された場合: `exec > >(tee ログファイル) 2>&1` で標準出力と同時にファイルに保存する。

### ユーティリティ関数

4. `section()`: セクション区切り見出しを出力する。
5. `subsection()`: サブセクション見出しを出力する。
6. `_aws_run()`: AWS CLI コマンドを実行し、正常取得・未存在・取得失敗を切り分けて出力する。リソース未存在パターン（`NoSuchBucket` 等）は `（未存在）`、その他のエラーは `（取得失敗: エラーコード）` と表示する。
7. `_aws_json()`: `_aws_run()` を呼び出し、正常時は `python3 -m json.tool` で JSON 整形して出力する。

### 情報収集関数

8. `info_iam_role()`: 指定 IAM ロールの信頼ポリシー・管理ポリシー一覧・インラインポリシー内容を出力する。

### メイン処理の流れ

9. 以下の順序でセクションごとに情報を出力する:

| セクション | 出力内容 |
|:---|:---|
| IAM ロール | build・exec・lambda・ec2 の各ロール詳細（`info_iam_role()` 使用） |
| IAM インスタンスプロファイル | `ts-010-role-ec2-010` プロファイルの詳細 |
| IAM ユーザー | `ts-010-user` の詳細・インラインポリシー |
| VPC | VPC 詳細・DNS 設定 |
| インターネットゲートウェイ | IGW 詳細・VPC アタッチ状態 |
| サブネット | サブネット詳細・パブリック IP 自動割り当て設定 |
| ルートテーブル | ルートテーブル詳細・ルート一覧・サブネット関連付け |
| セキュリティグループ | インバウンド・アウトバウンドルール詳細 |
| S3 バケット | in/out バケットのポリシー・ライフサイクル・バージョニング・暗号化 |
| CloudWatch | ロググループ一覧・保持期間・メトリックフィルター |
| SNS | トピック詳細・サブスクリプション一覧 |
| Lambda | 関数設定（コードハッシュ・環境変数・実行ロール） |
| EventBridge | ルール詳細・ターゲット一覧 |
| EC2 キーペア | キーペア一覧 |
| CloudTrail | 証跡詳細・イベントセレクター |

## 7. エラーハンドリング

- スクリプト先頭に `set -uo pipefail` を設定する（`-e` は意図的に除外: AWS CLI の失敗をエラーとして扱わないため）。
- `_aws_run()` により、リソース未存在と取得失敗（権限不足・ネットワークエラー等）を区別して出力する。いずれの場合も終了コード 0 を返すため、スクリプト全体の実行は継続される。
- 個別リソースの取得失敗は情報収集の続行を妨げない設計となっている。
