# mk-sg.sh 詳細設計書

## 1. 概要

### 1.1 目的

本スクリプトは、プロジェクト用のセキュリティグループ（`ts-010-sg-010`）を作成します。既存の同名セキュリティグループが存在する場合は削除してから再作成します。インバウンドルールは設定せず（EC2 自動処理用のため SSH 不要）、アウトバウンドはデフォルトの全許可です。

作成するリソース:
- セキュリティグループ（名前: `ts-010-sg-010`）
  - インバウンドルール: なし
  - アウトバウンドルール: デフォルト（全許可）

## 2. 実行環境

- 実行場所: `infra/` ディレクトリ
- 必要コマンド: aws cli
- AWS 認証: `source assume-role.sh`（`ts-010-role-build` を AssumeRole）

## 4. 入力

### 4.1 設定ファイル（config.sh）

| 変数名 | 説明 | 例 |
|:---|:---|:---|
| `VPC_NAME` | セキュリティグループを作成する VPC の名前タグ | `ts-010-vpc-010` |
| `SG_NAME` | 作成するセキュリティグループの名前 | `ts-010-sg-010` |
| `PRJ_TAG_KEY` | プロジェクト識別用タグキー | `PRJ_NAME` |
| `PRJ_TAG_VALUE` | プロジェクト識別用タグ値 | `ts-010` |

### 4.2 引数

コマンドライン引数はありません。

## 5. 処理フロー

### 初期化

1. `config.sh` を読み込み、環境変数を設定する。
2. `aws ec2 describe-vpcs` で `VPC_NAME` タグに一致する VPC ID を取得する。
3. 作業用一時ディレクトリ（`mk-sg.sh.src`）を作成する。
4. `trap` を設定し、ERR / INT / TERM シグナル発生時に `term()` を呼び出して一時ディレクトリを削除し、`exit 1` で終了する。EXIT シグナルでも `term()` を呼び出す。
5. ログファイル（`mk-sg.sh.log`）へのリダイレクトを設定する（`exec >> LOG_PATH 2>&1`）。

### `confirm_sg()` — 実行前後の確認

6. `aws ec2 describe-security-groups` で VPC 内の対象セキュリティグループ情報を表示する（存在しない場合はその旨を表示）。

### `make_sg()` — セキュリティグループ作成処理

7. `aws ec2 describe-security-groups` で既存セキュリティグループの GroupId を取得する。
8. 既存セキュリティグループが存在する場合:
   - `aws ec2 delete-security-group` で削除する。
   - AWS 反映待ちとして `sleep 5` を実行する。
9. VPC ID が空または `None` の場合はエラーメッセージを出力して `exit 1` で終了する。
10. `aws ec2 create-security-group` でセキュリティグループを作成する。
    - 説明: `For S3 trigger type shell script auto execution system`
11. `aws ec2 create-tags` でプロジェクトタグを付与する。

### メイン処理の流れ

12. 実行前に `confirm_sg()` を呼び出してリソース状態を記録する。
13. `make_sg()` を呼び出してリソースを作成する。
14. 実行後に `confirm_sg()` を再度呼び出して結果を確認する。

## 7. エラーハンドリング

- スクリプト先頭に `set -euo pipefail` を設定し、コマンド失敗・未定義変数参照・パイプエラーで即時終了する。
- `trap 'term; exit 1' ERR INT TERM` により、異常終了時は作業用一時ディレクトリを自動削除する。
- `trap 'term' EXIT` により、正常終了時も一時ディレクトリを削除する。
- VPC が見つからない場合は `exit 1` でスクリプトを終了する。
- すべての処理ログは `mk-sg.sh.log` に記録される。
