# 定義ファイル仕様書

## 1. 概要

### 1.1 目的
本文書は、S3イベント連携によるEC2自動処理における定義ファイル（.conf）の仕様を定めます。定義ファイルは、処理内容、通知先、実行環境などを指定するJSONファイルを指します。

### 1.2 関連文書

**参照文書**
- 要件定義書（[設計書/要件定義.md](要件定義.md)）
- 基本設計書（[設計書/基本設計.md](基本設計.md)）

## 2. 定義ファイル概要

### 2.1 基本情報
- **ファイル形式**: JSON
- **文字エンコーディング**: UTF-8
- **ファイル拡張子**: .conf
- **配置場所**: S3バケット（${BKT_IN}）
- **ファイル名**: 任意（拡張子に.confを指定）

### 2.2 処理フロー
1. 利用者が定義ファイルをS3バケットにアップロード
2. S3イベントがLambda関数をトリガー
3. Lambda関数が定義ファイルを読み込み・解析・検証
4. 検証通過後、EC2インスタンスを起動
5. EC2上で定義ファイルに基づいた処理を自律実行

## 3. JSON スキーマ定義

### 3.1 必須項目

| 項目名 | 型 | 説明 | 例 |
|--------|----|----- |----|
| exec | string | 実行するコマンド | "run.sh *.MOV" |
| log | string | ログファイル名 | "run.log" |
| result | string | 結果ファイル名またはパターン | "*.mp4" |
| mail | string | 通知先メールアドレス | "user@example.com" |
| sms | string | 通知先SMS番号（+81形式） | "+819012345678" |
| ec2_role_name | string | EC2用IAMロール名 | "ts-010-role-ec2-010" |
| subnet_name | string | サブネット名 | "ts-010-subnet-010" |
| sg_name | string | セキュリティグループ名 | "ts-010-sg-010" |
| ec2_instance_name_tag | string | EC2インスタンス名タグ | "ts-010-ec2-010" |
| output_bucket | string | 出力先S3バケット名 | "${BKT_OUT}" |
| ses_from_email | string | SES送信元メールアドレス | "sender@example.com" |
| prj_prefix | string | プロジェクトプレフィックス | "ts-010" |

### 3.2 オプション項目

| 項目名 | 型 | デフォルト値 | 説明 | 例 |
|--------|----|-----------|----- |----|
| ami_id | string | なし | 使用するAMI ID（指定時は `default_ami_id` より優先） | "ami-0123456789abcdef0" |
| default_ami_id | string | "ami-09ed31f8f34719e20" | デフォルトAMI ID（`ami_id` 未指定時に使用） | "ami-09ed31f8f34719e20" |
| instance_type | string | "c6i.4xlarge" | EC2インスタンスタイプ | "c6i.xlarge" |
| key_name | string | なし | SSH接続用キーペア名 | "ts-010-keypair" |
| ebs_size | integer | AMIのデフォルト | EBSルートボリューム容量（GB） | 50 |
| ebs_type | string | AMIのデフォルト | EBSボリュームタイプ（有効値: gp3, gp2, io1, io2） | "gp3" |
| timeout | integer | 3600 | タイムアウト時間（秒） | 7200 |

## 4. 検証ルール

### 4.1 必須項目の検証
- すべての必須項目が存在すること
- 値がnullまたは空文字列でないこと

### 4.2 形式検証

#### 4.2.1 メールアドレス（mail, ses_from_email）
- 正規表現: `^.+@.+\..+$`
- 例: "user@example.com" ✓, "invalid-email" ✗

#### 4.2.2 SMS番号（sms）
- 形式: "+81" で始まり、続く文字がすべて数字
- 例: "+819012345678" ✓, "09012345678" ✗

#### 4.2.3 EBSサイズ（ebs_size）
- データ型: 整数
- 範囲: 10以上1000以下
- 例: 20 ✓, 5 ✗, 1500 ✗

#### 4.2.4 EBSタイプ（ebs_type）
- 有効値: gp3, gp2, io1, io2
- 例: "gp3" ✓, "standard" ✗

#### 4.2.5 タイムアウト（timeout）
- データ型: 整数
- 範囲: 60以上21600以下（1分〜6時間）
- 例: 3600 ✓, 30 ✗, 25200 ✗

#### 4.2.6 文字列項目の長さ制限
- exec: 1〜500文字
- log: 1〜100文字
- result: 1〜100文字
- 各リソース名: 1〜63文字

## 6. エラーハンドリング

### 6.1 検証エラー
定義ファイルの検証に失敗した場合：
1. CloudWatch Logsにエラーログを出力します
2. 指定されたメール・SMS宛にエラー通知を送信します
3. 処理を中断します（EC2インスタンスは起動しません）

### 6.2 エラーメッセージの例
```
Configuration error: Missing required key 'exec'.
Configuration error: Invalid email format for 'mail': invalid-email.
Configuration error: 'ebs_size' must be between 10 and 1000. Found: 1500.
Configuration error: Invalid SMS format for 'sms'. Must be a string starting with '+81'. Found: 09012345678
```

## 7. 運用上の注意事項

### 7.1 セキュリティ
- 定義ファイル内に機密情報（パスワード、API キー等）を直接記載しない
- 実行コマンド（exec）では安全でないコマンドの使用を避ける
- SMS番号・メールアドレスは正確に入力します（誤送信防止）

### 7.2 性能考慮事項
- タイムアウト値は処理時間を考慮して適切に設定します
- EBSサイズは処理するデータ容量に応じて設定します
- インスタンスタイプは処理負荷に応じて選択します

### 7.3 コスト最適化
- 不要に大きなインスタンスタイプやEBSサイズを指定しない
- 処理完了後はEC2インスタンスが自動停止することを確認します

### 7.4 ファイル命名
- 結果ファイル（result）にはワイルドカード（*）使用可能
- ログファイル（log）は具体的なファイル名を指定することを推奨します
- ファイル名に日本語やスペースは使用しない
