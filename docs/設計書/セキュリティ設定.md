## 2. セキュリティ設定一覧

| 設定項目 | 付与先（対象リソース） | 設定内容 |
| :--- | :--- | :--- |
| **IAMロール** | Lambda起動関数 (`ts-010-lmd-010`) | **ts-010-role-lambda-010**<br>- S3入力バケットの読取（`s3:GetObject`, `s3:ListBucket`）<br>- S3出力バケットへの書込（`s3:PutObject`, `s3:ListBucket`）<br>- EC2インスタンスの起動・管理（`ec2:RunInstances`, `ec2:DescribeInstances`, `ec2:DescribeSubnets`, `ec2:DescribeSecurityGroups`, `ec2:CreateTags`）<br>- EC2へのロール付与（`iam:PassRole`, `iam:GetInstanceProfile`）<br>- SNSでの通知送信（`sns:Publish`）<br>- SESでのメール送信（`ses:SendEmail`）<br>- CloudWatch Logsへの書込（`AWSLambdaBasicExecutionRole` マネージドポリシー） |
| **IAMロール** | Lambda終了関数 (`ts-010-lmd-020`) | **ts-010-role-lambda-020**<br>- EC2インスタンスの削除（`ec2:DescribeInstances`, `ec2:TerminateInstances`）<br>- CloudWatch Logsへの書込（`AWSLambdaBasicExecutionRole` マネージドポリシー） |
| **IAMロール** | EC2インスタンス (`ts-010-ec2-010`) | **ts-010-role-ec2-010**<br>- S3入力バケットの読取（`s3:GetObject`, `s3:ListBucket`）<br>- S3出力バケットへの書込（`s3:PutObject`, `s3:ListBucket`）<br>- SNSでの通知送信（`sns:Publish`）<br>- SESでのメール送信（`ses:SendEmail`, `ses:SendRawEmail`）<br>- CloudWatch Logsへの書込（`logs:CreateLogGroup`, `logs:CreateLogStream`, `logs:PutLogEvents`）<br>- CloudWatch Agentの動作（`CloudWatchAgentServerPolicy` マネージドポリシー）<br>- 自身のインスタンス削除（`ec2:TerminateInstances`、Nameタグ条件付き） |
| **S3バケットポリシー** | S3バケット (`${BKT_IN}`) | `ts-010-role-lambda-010`（読取）および `ts-010-role-ec2-010`（読取）からのアクセスのみを許可します。 |
| **S3バケットポリシー** | S3バケット (`${BKT_OUT}`) | `ts-010-role-lambda-010`（書込）および `ts-010-role-ec2-010`（書込）からのアクセスのみを許可します。 |
| **S3パブリックアクセスブロック** | S3バケット (`${BKT_IN}`, `${BKT_OUT}`) | パブリックACL・パブリックポリシーをすべてブロックします（`BlockPublicAcls`, `IgnorePublicAcls`, `BlockPublicPolicy`, `RestrictPublicBuckets` すべて有効）。 |
| **S3サーバーサイド暗号化** | S3バケット (`${BKT_IN}`, `${BKT_OUT}`) | 全てのオブジェクトをAES256で暗号化します。 |
| **セキュリティグループ** | EC2インスタンス (`ts-010-ec2-010`) | **ts-010-sg-010**<br>- **インバウンド:** 全ての通信を拒否<br>- **アウトバウンド:** 全ての通信を許可 |
