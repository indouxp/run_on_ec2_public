### 1.3 テストID の命名規則

テストID は `<種別プレフィックス>-<連番>` の形式で付与します。

| プレフィックス | 種別 | 説明 |
|:---:|:---|:---|
| TF | 機能テスト（Functional Test） | 個別機能の正常系・異常系を検証する |
| TI | 統合テスト（Integration Test） | 複数機能を連携させた E2E フローを検証する |
| TS | セキュリティテスト（Security Test） | アクセス制御・権限設定を検証する |

## 2. 機能テスト詳細

### TF-001：.conf ファイルのアップロードで Lambda が起動すること

| 項目 | 内容 |
|:----|:----|
| 対象要件 | [001] S3イベント検知 |
| 前提条件 | リソース構築済み、`source work/.env` 済み |

**テスト手順**
```bash
# 1. 正常な run.conf を S3 にアップロード
cd work/
aws s3 cp run.conf s3://${BKT_IN}/

# 2. Lambda ログを確認（30 秒以内に起動ログが記録されること）
aws logs tail /aws/lambda/ts-010-lmd-010 --follow
```

**期待結果**
- Lambda ログに `START RequestId` が記録される
- EC2 インスタンスが起動する（TF-003 と合わせて確認）

---

### TF-002：.conf 以外のファイルでは Lambda が起動しないこと

| 項目 | 内容 |
|:----|:----|
| 対象要件 | [001] S3イベント検知 |
| 前提条件 | リソース構築済み |

**テスト手順**
```bash
# 1. .conf 以外のファイルをアップロード
echo "test" > test.txt
aws s3 cp test.txt s3://${BKT_IN}/

aws logs describe-log-streams \
  --log-group-name /aws/lambda/ts-010-lmd-010 \
```

**期待結果**
- Lambda ログに新しいストリームが作成されない（直近のタイムスタンプが変化しない）

**後処理**
```bash
aws s3 rm s3://${BKT_IN}/test.txt
```

### TF-010〜TF-018：EC2 処理フロー・通知・ログ（正常系）

> **注意**: TF-010〜TF-018 は 1 回の実行で連続して確認します。

**共通前提条件**
- テスト用 run.sh（即時終了するダミー）を用意する
- 小容量の tarball（テスト用入力ファイル）を用意する

```bash
# テスト用 run.sh（ダミー）
cat > /tmp/run.sh << 'EOF'
#!/bin/bash
echo "test run: $(date)"
echo "test output" > test_result.txt
EOF

# テスト用入力ファイル
echo "dummy" > /tmp/input.txt
tar czf /tmp/test_input.tar.gz -C /tmp input.txt

# S3 にアップロード
aws s3 cp /tmp/run.sh s3://${BKT_IN}/run.sh
aws s3 cp /tmp/test_input.tar.gz s3://${BKT_IN}/test_input.tar.gz
```

**run.conf（テスト用）**
```json
{
  "exec": "run.sh test_input.tar.gz",
  "log": "run.log",
  "result": "test_result.txt",
  "mail": "（実際の通知先メールアドレス）",
  "sms": "（実際の通知先電話番号）",
  "ec2_role_name": "ts-010-role-ec2-010",
  "subnet_name": "ts-010-subnet-010",
  "sg_name": "ts-010-sg-010",
  "ec2_instance_name_tag": "ts-010-ec2-010",
  "output_bucket": "${BKT_OUT}",
  "ses_from_email": "（実際の SES 送信元アドレス）",
  "prj_prefix": "ts-010",
  "instance_type": "t3.micro"
}
```
