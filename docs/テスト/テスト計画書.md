## 2. テスト方針

- 要件定義書の機能要件 [001]〜[012] をすべてテストケース化し、個別に検証する
- テストは実際の AWS 環境で実施する（テスト専用環境は設けない）
- 確認は AWS CLI コマンドおよび CloudWatch ログで行う
- 異常系テストは Lambda バリデーション層で検出できるものを対象とする
- EC2 上のシェルスクリプト（run.sh）の内部ロジックはテスト対象外とする（ユーザー責任）

---

## 3. テスト対象とスコープ

### 3.1 テスト対象コンポーネント

| コンポーネント | テスト内容 |
|:------------|:---------|
| S3 イベント通知 | `.conf` ファイルのみ Lambda が起動すること |
| Lambda 起動関数（ts-010-lmd-010） | 定義ファイル検証・EC2 起動・エラー通知 |
| EC2 UserData スクリプト | ファイル DL・シェル実行・S3 アップロード・通知・自己停止 |
| Lambda 終了関数（ts-010-lmd-020） | EC2 インスタンス削除 |
| EventBridge ルール | EC2 停止イベント検知 |
| SNS / SES | SMS・メール通知の到達確認 |
| CloudWatch Logs | ログ出力の確認 |
| IAM / S3 バケットポリシー | アクセス制御の確認 |

### 3.2 テスト除外項目

| 除外項目 | 理由 |
|:--------|:----|
| run.sh の内部ロジック | ユーザーが作成するスクリプトであり本システムの責任範囲外 |
| AWS マネージドサービスの内部動作 | AWS が保証する範囲 |
| 並列実行 | 初期リリースでは非対応 |
| 性能テスト（繰り返し実行） | コスト制約により最小限にとどめる(インスタンスタイプ精査のみにとどめる) |

## 4. テスト種別

### 4.1 機能テスト（TF: Test Functional）

要件定義書の機能要件 [001]〜[012] に対応したテストケース。

| 分類 | テストケース ID | 対象要件 |
|:----|:-------------|:-------|
| 正常系：S3 トリガー | TF-001, TF-002 | [001] |
| 正常系：定義ファイル解析 | TF-003 | [002] |
| 異常系：定義ファイルバリデーション | TF-004〜TF-009 | [003] |
| 正常系：EC2 処理フロー | TF-010〜TF-015 | [004]〜[008] |
| 正常系：通知 | TF-016, TF-017 | [009][010] |
| 正常系：ログ | TF-018 | [011] |
| 異常系：シェルスクリプトエラー時 | TF-019, TF-020 | [005][009][010] |
| 正常系：EC2 削除 | TF-021 | [004] |

### 4.2 統合テスト（TI: Test Integration）

S3 アップロードから EC2 削除までの E2E フローを 1 ケースで通して検証。

| テストケース ID | 内容 |
|:-------------|:----|
| TI-001 | E2E フロー（アップロード → Lambda → EC2 処理 → 通知 → 自動削除） |

### 4.3 セキュリティテスト（TS: Test Security）

IAM・セキュリティグループ・S3 バケットポリシーのアクセス制御を検証。

| テストケース ID | 内容 |
|:-------------|:----|
| TS-001 | S3 バケットへのパブリックアクセスが拒否されること |
| TS-002 | EC2 へのインバウンドアクセスが拒否されること |
| TS-003 | 不正 IAM ユーザーからの S3 アクセスが拒否されること |

## 5. テスト環境

| 項目 | 内容 |
|:----|:----|
| AWS アカウント | 本番と同一アカウント |
| リージョン | ap-northeast-1（東京） |
| Lambda 関数 | ts-010-lmd-010, ts-010-lmd-020（本番と同一） |
| EC2 インスタンスタイプ | t3.micro（テスト用途の最小構成） |
| テスト用 run.sh | 即時終了するダミースクリプト（コスト最小化） |
| テスト用入力ファイル | 小容量ファイル（数 KB 程度の tarball） |
| 実行端末 | AWS CLI 設定済みのローカル端末 |

## 6. テスト実施前提条件

テスト開始前に以下をすべて確認してください。

| # | 前提条件 | 確認方法 |
|:--|:--------|:-------|
| 1 | 構築確認チェックリストがすべて ✅ であること | [構築手順/構築確認チェックリスト.md](../構築手順/構築確認チェックリスト.md) 参照 |
| 2 | `source work/.env` 済みで `AWS_ACCOUNT_ID` が設定されていること | `echo ${AWS_ACCOUNT_ID}` |
| 3 | SES 送信元メールアドレスが検証済みであること | AWS コンソール → SES → Verified identities |
| 4 | 通知先メールアドレスが受信可能であること | 受信確認 |
| 5 | 通知先電話番号（SMS）が有効であること | SIM 確認 |
